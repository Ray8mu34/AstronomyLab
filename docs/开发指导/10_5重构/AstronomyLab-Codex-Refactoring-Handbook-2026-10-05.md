**主交付：原始讲义资料包、独立演示运行包、全站基础改造、两个深度样板。**

本手册将已经确认的产品边界转为可执行开发任务。当前 GitHub 主分支与《AstronomyLab 功能与设计说明》采用同一提交；这不意味着开发者本机没有后续修改。开工先检查本地工作区，不得为了对齐本手册而覆盖后来产生的工作。现状依据来自固定版本 PDF 与源码静态阅读；编写本手册没有新增浏览器、模型精度、设备性能或真实试讲验收。各项“应实现”“应通过”均为目标，不是现成能力。[S01–S03]

这次工作不是重新制作16讲，也不是把43个模式一次性重写为统一仿真引擎。**先真正解除内容依赖，再让现有演示可以独立说明一个有边界的问题。** Lab 可以逐步容纳交互仿真、机制演示、数据探索与视频，但必须由已经存在且有价值的内容推动，不提前搭建空的媒体平台。

## 1. 已经确定的产品定位与本轮范围

### 1.1 对象保持独立

**讲义是内容资产。** 16份原始 `lesson.md` 继续作为完整长文的维护源，保留段落、公式、图注、锚点、来源和相对链接。本轮不改写、删减、重新编号或插入课程平台元数据。将它们与实际依赖的图版、来源文件一起导出，形成脱离 Lab 工作区仍可保存与使用的资料包。未来 PDF、静态 HTML 和课件从这一内容体系制作；它们不是 Lab 工具运行的前提。

**Lab 是独立演示工具集合。** 用户不阅读任何一讲，也应能理解当前演示的对象、一个核心问题、第一步操作、值得观察的变化，以及模型不适用于什么。保留必要解释和公式，但不把整个讲义复制进控制面板。脱离讲义，是解除运行依赖和讲次依赖，不是取消解释、出处和科学边界。

今后课程引用工具，工具不认识课程编号。Lab 内部各工具也不需要共享一个模拟宇宙：几何模型、数据图像、二维曲线与模型轨道浏览允许使用不同呈现方式。统一的是少量操作习惯和交付质量，不是全部科学计算。[S02]

### 1.2 本轮 R1 必须交付什么

| 工作范围 | R1 完成定义 |
|---|---|
| 原始讲义 | 全部16份原始 Markdown 和可追踪依赖导出；原始字节不变；没有第二套手工维护的正文 |
| 产品结构 | 首页、导航、注册表、工具运行与素材访问不依赖课程目录；讲义转为独立资料，旧路径由隔离的兼容层处理 |
| 全站基础改造 | 11个工具、43个模式全部核对并保留入口；每个模式具备独立语境、第一步操作、必要边界和可工作的基本控制 |

“全部43个模式已做基础适配”和“全部43个模式都完成深度重制”必须分开报告。其余37个模式的进一步视觉升级按第11章分批继续，不能在 R1 末尾笼统写成“全站演示质量验收通过”。反过来，也不能只做好两个样板就宣称整个 Lab 已解耦。

### 1.3 本轮明确不做

不重写16讲；不批量生成16套 PPT 或教学视频；不建设账号、成绩、题库、学习进度、云端课程编辑器、统一物理引擎、插件市场、跨站桥接系统。没有实际可用视频时，不建设空的视频频道、制作工作台或片单。不为抽象的未来扩展强制迁移 React、Vue、TypeScript、打包框架或仓库体系。

R1 默认保留现有模式 ID 和公开入口；合并或下架模式必须另有功能去向、兼容策略和负责人确认。只允许对工具所需的短说明进行有依据的改写，不能把未经验证的新模型包装为原模型的界面优化。

默认只在本地执行开发与验证；不推送、不发布、不连接生产服务器，不改社团主站、Sky 或其他项目的配置。版本提交遵守当前工作区授权规则；部署单独批准。[S03]

## 3. 开工保护与工作区约定

### 3.1 先建立真实基线

阅读 `AGENTS.md`、`README.md`、部署说明和当前差异。使用原生 Windows PowerShell 7；需要 Python 时使用已有 Conda `dl_env`。运行保持 Node.js 22 体系，不因本轮开发给服务器安装 Python、Conda 或构建环境。已有开发环境可以复用，不先升级全部依赖。[S03、S15]

在当前工作区记录 `git rev-parse HEAD`、`git status --short` 和相关未提交差异。检查是否已有 `studio/`、视频素材、独立讲义导出、界面分支或其他后续工作；这些只是需要检查的对象，不是本手册确认它们一定存在。对未跟踪文件同样建立保护记录。不得执行 `git reset --hard`、`git clean`、自动覆盖式拉取或擅自 stash 来制造“干净基线”。

若本地比本手册版本新，以本地有效成果为实现起点，把差异登记出来；只调整确实不适用的文件定位，不撤销已确认的产品边界。多人或子代理并行前先确定文件所有权。

### 3.2 把保护对象分为三类

**字节保护：** 16份原始 Markdown、已有科学输入数据、原始图像和许可证。以本机开工时的真实文件字节生成 SHA256；同时记录 Git 提交与工作区是否有修改。Git blob、检出后的换行、BOM 和文件编码可能不同，不能把三者混为同一基线。归档至少保住开工时用户正在维护的版本，不能用远端旧文件替换。

**行为保护：** 已有模型、单位、有效范围、输入含义、状态恢复、旧入口、安全路径白名单。模型和渲染位于同一个文件时，不能用“改了 UI 所以整个文件不再受保护”跳过计算结果回归；应保护具体计算逻辑和对应测试样本。

**允许改造：** 工具入口、注册表拆分、布局、短说明、非必要课程提示、模式切换表达、可访问性、失败反馈和发行脚本。界面说明改写要有原有模型文档支撑，来源信息可以重新组织但不能消失。

发现明显的科学错误时，记录复现输入、原结果和依据，隔离该问题；停止使用错误结果作为新演示的论据。需要修正模型的，单列差异与针对性测试，报告这是科学改动而非界面整理。尚不能确认的科学变化不纳入“保持原模型”的承诺；争议不应阻止无关模块继续工作。

### 3.3 保持工作产物简单

建议只新增一份持续维护的 `docs/LAB-REFACTOR-2026-10-05.md`，记录范围、进度、决策和交接；机器清单、截图和录屏放在忽略版本控制的 `build/qa/lab-refactor/`。原始讲义包、运行包放在 `dist/`。确需长期维护的用户说明与公开模型记录留在各自明确位置，不创建几十份空白设计文档。

## 4. 讲义解耦：原始 Markdown 必须成为完整资料包

### 4.1 交付的不是16个失去图片的文本文件

以第03讲为例，正文引用 `../../assets/03/v02/moon-phases.png`，也引用 `../../assets/v02-reference/SOURCES-pro-01-04.md#s44`。只复制 `lesson.md` 会让图与依据丢失。因此归档需要保留原路径关系，并收集实际依赖，而不是重新书写正文链接。[S11]

本轮保持仓库内 `course/` 为唯一正文维护源；不为了“独立”立刻把它移动到另一个仓库。**独立首先由资料包和运行依赖证明，而不是由仓库数量证明。** 导出的包是带版本的发行快照，不是第二套可以随意手改的主文件；未来正式拆仓库时再明确切换唯一维护源。

建议输出如下。只创建真正需要的目录与文件：

```text
dist/lectures-source/
  README.md                  # 怎么使用、维护源在哪、分发状态
  manifest.json              # 版本、路径、哈希、依赖与未决事项
  course/
    01-solar-system/lesson.md
    ...                      # 原来的16个目录名，保持相对层级
  assets/
    ...                      # 正文和来源真正使用的本地依赖
  credits/
    ...                      # 实际需要携带的许可或署名记录
```

`README.md` 和清单是新增旁车文件，不插入 `lesson.md` 的开头，不修改标题、不重排引用、不把图注改成新标题。外部网页链接保留为来源入口，不自动把整站下载进来，也不宣称归档拥有这些网页。

### 4.2 依赖收集要求

先枚举 `course/*/lesson.md` 并确认恰好覆盖01–16；再使用已有 Pandoc AST 与 HTML 解析能力读取图片、普通链接、引用式链接、内嵌 HTML 的资源路径和本地来源文件。递归处理被引用的本地说明、图片、必要样式及其资源，但应去重、记录循环、限制在批准的资料范围内。不能只用一个 Markdown 图片正则完成所有收集。[S12]

路径解析时分开文件路径、查询参数与锚点，正确处理中文和百分号编码；按实际文件系统检查大小写及符号链接最终去向。依赖清单对每个文件记录原路径、用途、SHA256、引用者和目标包路径。既有显式锚点原样保留；构建派生网页时再验证自动生成标题锚点。

原卷、教师记录、私有 QA、凭据、`.env`、原始科学数据压缩包不能因为被某份旧说明链接到就自动进入公开资料包。遇到这类引用，登记为非公开依赖；保留原始源文件不动，不为了消除失效链接而开放私有文件。其他真正缺失的本地图或来源要准确列出，不能编造一幅相似图片替代。只有必需依赖全部存在时，才能声称资料包完整。

若既有脚本将来源记录处理为派生 HTML，可以复用其解析与审计逻辑，但原始 Markdown 资料包仍保留原始文件。不要用渲染后的纯文本或重新导出的 Markdown 冒充“原始 md”。

### 4.3 私有保存与公开分发分别处理

当前报告与项目记录把 MIST衍生数据、M17教育FITS衍生数组和月球近远面组合图的再分发状态列为待核。归档已有文件以避免成果丢失，与再次公开发布不是同一件事。先完成本地保存并保留待核记录；需要这些素材而许可尚未核实的包，标为“本地资料归档，公开分发待确认”，不得擅自上传或宣称自由再分发。[S01、S16]

为公开发行检查时，未解决的必要素材要阻止该发行项通过，或在负责人批准后采用明确替代方案。不能删除来源警告、自动换成随机生成图片，也不能把一个缺图版本称为完整讲义。许可问题不阻止代码拆分、合成数据样板或本地检查继续进行。

### 4.4 验收讲义独立性

将资料包复制到仓库之外的临时目录，从那里打开原始 Markdown，并检查全部16讲的图片和本地来源。对源和归档逐文件比对字节哈希，确认公式、段落与锚点没有被格式化器重写。生成机器可读的缺失依赖与非公开依赖报告；不要仅用“压缩包存在”作为完成条件。

本轮必须交付原始资料目录、压缩包和清单。PDF、PPT 不作为完成这一阶段的前提。可以利用已有 HTML 导出制作**独立静态阅读副本**作为旧链接兼容或后续分发基础；它是派生结果，不是新的主内容。构建副本时，将运行时的路径改写移到构建过程，不把旧 Lab 导航或 SPA 脚本重新注入。

## 5. 运行解耦：一套轻量入口，若干独立工具

### 5.1 最小目标结构

保持现有 `web/observatory/`、`web/solar-system/`、`web/earth-moon/` 的实现位置，优先做职责拆分，不先全仓库搬家。建议形成三个互不依赖的输出：`dist/lab/` 是工具运行包，`dist/lectures-source/` 是原始资料包，确有构建需要时 `dist/lectures-web/` 是派生阅读包。只有后两者需要正文；Lab 构建不能通过扫描讲义来推导自己的导航、图层或公开资产。

可以继续使用本地 Node 静态服务与现有模块结构。R1 不要求所有旧完整页面都改写成 SPA，也不要求一个 HTML 文件包含全部资源。两种工具入口的运行差异由一个轻量目录遮蔽即可；工具本身要保持直接访问能力。

### 5.2 拆出无课程信息的工具注册表

新增 `shared/tool-registry.js`，集中管理稳定的工具 ID、显示名称、入口、模式与主题。将 `confirmedModes`、`labURL`、`experimentURL` 等中性能力迁入；注册表不包含 `lessons`、`tag: '03—04'`、原文锚点或课程路径。优先保持既有模式 ID、普通 URL 与默认模式不变，展示名称可更清楚。

`lessonEntries` 和45条课程段落映射归内容侧或隔离的旧阅读适配模块；工具模块不能反向导入它们。迁移期允许 `course-map.js` 为旧阅读与测试重导出兼容数据，但新工具入口、共享控件和模式模块不得再通过它获取中性能力。用导入图检查防止“文件改名了，课程数据仍被间接加载”。[S04、S05]

如需简短目录说明，保持一个真实的小对象即可，例如：

```js
// 提议的新记录；具体模块路径沿用既有实现，不是通用插件协议。
{
  id: 'earth-moon',
  title: '日地月',
  topic: 'space',
  entry: '/labs/earth-moon/',
  modes: ['phase', 'spin', 'period', 'eclipse'],
  summary: '改变光照、运动和对齐条件，比较空间关系与所见。'
}
```

不要为尚未存在的模块添加能力占位、未来模式、复杂依赖声明或动态插件加载器。模式级帮助放在真正使用它的模块；只有两个实际实现证明存在共同需求时，才提取小型共享结构。

### 5.3 拆开运行、阅读和绘图依赖

把 `app.js` 中工具首页与实验路由的运行路径同阅读、课程目录、素材检索分开。新首页不读取原 `catalog.json`；实验进入和失败反馈不依赖文章是否存在。阅读兼容路径可独立按需加载，不能成为主入口的静态导入前提。现有 `load-content.js` 的请求取消、过期请求处理和错误提示按职责保留，不为了拆文件重写一遍。

把 `shared/lab.js` 中的纯控件、二维绘图和三维场景辅助分开；`lessonLinks()` 移出工具共享层。图像或曲线模式只在确有三维图需要时才加载三维相关代码，不要求所有模式先创建 WebGL 上下文。原有辅助函数的调用语义与单位不因拆分改变。[S06、S07]

旧 `navigation.js` 不再导入课程段落映射，也不监听“实验变化后更新对应文章”的主链路。其承担的旧版工具状态初始化、焦点处理、`pagehide/pageshow` 和 bfcache 恢复要迁到工具启动文件。不要因为删掉课程导航而顺手丢失这些行为。[S05]

### 5.4 拆开素材访问，不拆掉科学依据

从工具入口出发收集实际使用的纹理、图像、数据、来源说明和许可证，生成独立的 `runtime-assets.json` 或同等清单。部分资产同时被正文和工具使用，可以仍以仓库中同一原文件为维护源，在两个发行包中复制；这不是两套手工维护的数据。

`server.mjs` 的工具资产白名单改为读取此清单，不再读取课程目录 `catalog.json`。清单需覆盖真实运行依赖，包括共享自太阳系的 vendor 与 textures。不能使用“所有 `/assets/**` 均可访问”来解决404，更不能让 `dist/lab/` 包含整个工作区。[S08]

模型说明、数据元信息与署名属于工具的必要依赖，必须保留；“来源与模型”仍然可以是主导航的一个轻量入口。把面向开发过程的大段验证叙述移到次级说明，不将必要的比例、数据身份和模型限制一同藏掉。

### 5.5 对两类现有实现分别处理

九个挂载式模块继续使用现有 `mount` 与清理机制；以局部改造逐步形成更清楚的模块所有权。太阳系与日地月暂时保留完整页面、import map 与本地依赖。它们需要各自启动就具备工具导航和初始化，而不是必须依赖服务端注入课程脚本才能使用。

原日地月 `content.js` 和类似文件先按字段追踪消费者：模式解释、公式、观察提示若能独立成立，保留并去掉课程语境；整讲正文、按讲次打开的对话框和课程图版浏览则移出运行包。不要根据文件名含 `content` 或 `reading` 就直接删除。太阳系内已有对象介绍和数据资料也不等于整讲讲义，应继续保留有用的对象说明。[S09、S10]

### 5.6 解耦的硬证明

在临时运行包中不包含 `course/`、`build/articles/`、课程目录数据、课程段落映射和整讲阅读文件；不依赖它们的服务路由，仍能进入所有保留的工具模式。用浏览器请求记录和静态导入图共同验证。可以允许显式点击的外部资料链接，但不能在后台自动加载讲义。

测试应按“课程文件/端点”隔离，而不是粗暴封禁所有原来属于某讲的 `/assets/03/...`；同一图像若确为工具运行所需，已进入工具独立清单，就不是课程运行依赖。构建时故意移走课程内容，应只影响课程资料构建，不应使 Lab 构建失败。

## 6. 入口、兼容与发布方式

### 6.1 首页是工具目录，不是课程宣传页

新首页用简短介绍和实际工具目录直接进入内容。建议主导航只保留“演示工具”“来源与说明”；“讲义资料”作为次级、普通链接或下载入口，不能继续占据主页主体。首页不要同时展示旧课程口号、四层分类、巨幅装饰图、16讲目录和全部模式详情。

可以沿用四个主题作为目录索引，但去掉讲次范围。每条工具入口只需要清楚名称、一句可做的事情和一张真实代表截图，或干净的文字目录；二者任选适合实际版面的形式，不要求每项都塞进大圆角卡片。目录中的图必须对应实际工具，不使用装饰宇宙图片暗示未实现的效果。不要新增“敬请期待”视频区或虚构内容数量。

工具页顶部以名称、模式选择、返回工具目录为主。不再出现“第03—04讲”“从试卷讲起”“先读本讲”“读完这一段再继续”等课程依赖式文案。必要的帮助改为当前工具的自足说明，而不是要求用户离开应用去找原文。

### 6.2 旧 URL 的兼容是独立服务，不是把课程留在核心里

| 既有入口 | R1 的处理 |
|---|---|
| `/labs/solar-system/`、`/labs/earth-moon/` | 保留，保持 `mode` 可用；完整页面能独立初始化 |
| `/lab/{slug}?mode=...` | 保留当前有效入口；任何新规范路径都必须有兼容映射 |
| `/courses`、`/read/NN`、`/reading/LNN.html` | 由隔离的资料兼容层处理，不走工具加载链 |
| `/materials` | 转为独立资料入口或资料包的检索页；不再作为工具资源权限来源 |
| `?from=...` | 工具端允许忽略旧课程来源参数，不加载课程映射；核心演示不受影响 |
| `?ui=classic` | 迁移期保留已承诺行为，或明确迁移到新界面并记录；不得暗中造成模式丢失 |
| 来源、元信息与许可证路径 | 保留必要公开入口；不能把资料独立化变成删除署名 |

当前尚未确定讲义的正式新部署地址，因此不能编造主站路径、提前改生产重定向或把地址写死。开发期可由兼容服务读取外置 `lectures-web` 包；工具运行包不携带整讲正文。没有外置资料包时，旧阅读路径显示明确的资料位置说明与可用的资料入口，而工具仍可工作。正式部署前必须解决旧链接去向；说明页只是开发期回退，不是长期迁移完成的证据。

若以后重定向到其他域名，使用配置中的受信任目标而不是任意 `returnTo` 或输入 URL。文章锚点位于浏览器 fragment，服务端通常不直接收到；迁移测试必须实际从带中文锚点的旧地址打开，检查跳转后的锚点和编码，不能只用 HTTP 状态码判断。[S08]

### 6.3 独立发行不强求单文件与全静态改造

R1 工具包可以继续携带一个最小本地 Node 服务，或采用经过验证的静态发行结构。目标是“没有课程也能运行”，不是“立即删除 Node”。原服务器承担过路径适配、资源权限和旧页面注入；这些工作必须在新构建或轻量服务里得到明确承接。[S08]

讲义派生网页适合成为静态目录包；浏览器中执行模块和数据请求的工具，则需要另行证明本地打开方式。不得把 `file://` 双击完整目录失败归咎于用户，也不得把 localhost 运行说成单文件离线。发行说明应分别写清：是否需要 Node、如何启动、是否首次使用就不需要外网、数据是否齐全。

R1 不为兼容子目录部署重写每个路径；讲义静态包应支持相对路径，Lab 若仍需部署在站点根路径则明确记录。只有实际需要把工具放到主站子目录时，才增加统一基础路径适配。

## 7. 演示的 UI 与内容规范

### 7.1 自足，但不把长文搬进来

每个模式都要给出一个完整的小解释单元：说明当前对象和问题，提供可以立即执行的操作，让画面和读数显示关系，并让用户有办法理解结果与边界。它不承担整讲背景，也不要求先完成上一模式。直接打开某个 `mode` 链接，应该就是一个可以开始使用的演示。

建议每个模式的默认文案包括一个具体问题、一句操作提示和一个观察重点；这些可以整合成自然的两三句话，不一定做成三个标签。次级帮助用两三段完整文字解释机制与适用条件，必要时附一个公式与来源。长度是为了控制界面负担而提出的设计建议，不是必须凑满的模板；已有说明足够好时直接复用。

例如月相模式可以采用：“拖动月球，观察地球所见的亮面怎样改变。太阳始终照亮月球朝向它的一半；变化的是观察者看见的受光部分。”这段话不需要讲次背景，也不需要在主画面常驻整篇月相讲义。月球总亮度、地照和地质等更广内容仍留在讲义里。[S09、S11]

### 7.2 三种工作区，不是一种通用仪表盘

**空间与运动工作区**以对象和几何关系为视觉中心。需要比较观察方向时才出现第二视图；第二视图可以临时成为主视图。相机、轨迹和标记用来帮助保持对象身份，不把关键变化长期缩在角落的小窗里。

**曲线与数据工作区**以可读的坐标、数据身份、当前点和比较关系为中心。二维图并不低级；应改进其标签、刻度、参考线和操作关系，而不是为了显得“科学平台”强加三维球体。自动归一、坐标缩放和对数轴必须有清楚含义，避免参数改变后图被重新缩放得看起来没变。

**图像与测量工作区**以源图、处理结果、检查位置和可复核的测量为中心。原数据与显示效果分开，比较时尽量保持位置和显示尺度一致。对照、撤销人工偏移、像素读数等应靠近图像，而不是埋在长页面底部。

统一标题、模式选择、复位、帮助和错误反馈的交互，不强制所有模块共享一条时间轴、同样数量的滑杆、同一画布布局或同样的背景色。

### 7.3 默认界面的具体约束

在桌面首屏，当前科学对象与主要操作应同时可见。以1366×768为低高度桌面检查点，1920×1080为常用演示检查点；图形区优先占据主要宽度与高度。三维样板可从“约三分之二宽的主舞台＋约280–340像素的可收起控制区”开始，但最终服从关键关系是否看得清，不把该比例当成所有模块的硬模板。

标题区应简短；不要让品牌、口号、简介、模式说明和操作说明连续堆叠，把科学对象挤到首屏下方。默认只展开当前模式需要的主要参数，额外模型设置与完整解释折叠。不能通过统一 `overflow:hidden` 裁掉多余内容来通过截图，也不能把所有细字藏进 tooltip 伪装清爽。

对象标签、刻度和单位要在实际投影尺寸下检查。可以用正文16像素左右、投影模式关键标签18–22像素作为起点；这些是设计目标而非设备可读性认证。Canvas 文本也要随投影布局调整，不能只改 DOM 字号。长读数使用合理有效位数、稳定宽度和明确单位，避免每一帧文本变化让布局抖动。

线条、颜色和明暗必须服务于关系。相同角色跨视图采用一致编码，并辅以标签或线型；不要仅靠红绿区分。减少大圆角容器、装饰图标、无意义英文口号、玻璃拟态和随机星空背景。真正有空间对象的场景可以保留深色舞台与合适材质；二维数据工具不必强制套宇宙外观。

### 7.4 连续性比“会动”更重要

运动类演示必须让用户追踪同一个对象、看见一个条件如何连续变化，以及结果在何处出现。端点预设用于便捷复现，不能代替过程。禁止把多个固定状态淡入淡出后宣称完成连续机制演示；也不能只让球体匀速绕圈，却把关键解释全部留给旁边的文字。

例如两种月周期的关键不是让月球走一圈，而是让“回到恒星方向”和“再次回到同样月相”两个终点在同一连续过程中可见。到达端点后可以暂停、标记参照方向，继续推进时保持对象身份和方向约定。必要时切换视角，但不要让相机自动绕行妨碍讲解。

科学运动可以在画面暂停时被解释；减少动态偏好的用户应有静态关键状态或手动步进。禁止用超高播放速度掩盖运动方向、采样不足或错误的轨迹插值。

### 7.5 演示模式与交互细节

提供轻量“演示布局”：收起网站目录与次要控制，增大舞台和核心标签，保留暂停、复位、退出及当前状态。不要另建一套不同科学状态的演示页面，也不必做多屏讲者控制台。退出演示布局后相机、参数和选择保持；浏览器全屏不可用时仍可以使用页面内大舞台。

快捷键只在合适焦点范围生效，不能让用户在数值框输入时误触播放、复位或切模式。Escape 关闭最近的面板并恢复焦点；交互按钮可用键盘；拖拽物体应提供等效的数值、滑杆或预设操作。不要截获全页面所有方向键和空格。

触屏与窄屏保留一个可操作主视图，必要时切换“空间关系／观察结果”，不把两个画布同时压成无法辨认的缩略图。切换可见视图不重置模型；被隐藏的重渲染视图应避免无意义消耗。320像素与390像素视口、200%缩放检查没有横向整页溢出；数值输入、弹窗和底部控制不能互相遮挡。视口模拟通过不等于实体手机验收。

### 7.6 解释能力的内容验收

每个模式至少能回答：当前显示什么；我改变了什么；画面哪个部分回应了变化；这个关系说明什么；什么时候不能这样解释。不要写五个问题让用户考试，而是用实际对象、操作和说明共同承担这些信息。

每个模式必须有一条无需讲义的可复现演示路径，以及一个能显示边界或反例的参数变化。路径可以写在测试记录中，不要求在界面做强制教程或逐步解锁。新的长说明只补足必要机制，不能借“独立使用”把一份工具重新扩成百科网站。

## 8. 状态、模型与运行质量

### 8.1 科学量与显示量分开

理想化几何、解析关系、模型表浏览、观测衍生数据和合成数据应分别标明。为教学放大的球体尺寸、压缩的距离、图像显示增益，不得回写物理量。场景看起来像真实天空，不代表具有任意日期的星历预测能力；连续浏览模型表也不代表实时求解恒星演化。[S01]

不为了连贯动画而线性插值本不适合插值的数据，尤其不能在三个离散质量的模型之间造出未验证的恒星演化轨道。若插值仅用于相机或视觉转场，注明它不产生新的科学状态。量的归一化、有效范围和退化情形由具体模块负责。

### 8.2 保住现有恢复，再提升两个样板

当前状态系统已经通过白名单控件恢复参数，并按历史项区分不同访问，具有存储失败时的内存回退。先把它对课程注册表的依赖改为工具注册表，保留这些行为。不要将页面后退的恢复等同于可以跨电脑完整重现的场景文件。[S13]

两个深度样板增加或整理一个小型显式接口，让界面、预设、复位与导入走同一条验证路径。接口只在真实样板需要时出现，其他模块可以继续用原适配器，不强制全部43个模式迁移。

```text
getState()                 读取可保存的科学输入与展示状态
applyState(candidate)      完整校验后原子应用；失败不破坏当前场景
reset()                    恢复当前已载入起点，并暂停
pause()                    暂停，不改时间、参数与相机
resize()                   改变显示尺寸，不改科学状态
dispose()                  释放本实例拥有的事件、计时与渲染资源
```

它不是外部任意脚本执行接口，也不是统一所有工具物理状态的基类。若原实现已有同等能力，直接复用，不重复包一层名称相同的接口。

### 8.3 复位和保存行为说清楚

首次进入模式，使用该模式默认起点。载入一个预设或导入场景后，“复位”回到这个起点并暂停；“恢复模式默认”是单独的次级操作。手动改变参数后不能悄悄覆盖复位基准。切模式是否保留时间、比较图或相机，应由模式契约明确，不能依靠偶然的 DOM 重建结果。

样板的场景导出至少记录工具 ID、模式 ID、格式版本、模型版本、必要数据版本或哈希、科学输入、关键展示选项和能影响结果的随机种子。日地月保存相机与参考方向；图像保存数据集身份、像素选择和处理参数。是否携带对照快照必须明确：推荐 R1 重新打开时清空临时对照并提示，避免把没有保存的比较图说成“完全复现”。

场景是输入配方，不是把图像数据数组、整篇说明、贴图或教师记录塞进 JSON。图像已有的“保存处理信息”先检查其实际内容；可以扩展成兼容的新场景配方或另设明确格式，不得把旧导出静默解释成包含相机、种子与比较缓存的完整存档。[S10]

导入采取白名单字段、类型、数值有限性、范围、枚举、长度与版本校验；未知重大版本拒绝并保留原场景。具体大小上限按实际文件测量后确定，例如小型场景64 KiB量级即可，不接受任意脚本、资源 URL 或路径。提供失败原因，不能部分应用后留下混合状态。跨数据版本不兼容时明确拒绝，不能退回默认数据却显示“已恢复”。

### 8.4 生命周期与性能

每个工具实例拥有自己的模拟时钟和资源；路由离开、弹出独立页面关闭或模式卸载时，停止回调、解绑事件并释放实例拥有的 GPU 资源。共享资源由明确所有者释放，不能某个视图销毁时把另一个仍在使用的纹理删除。

页面隐藏时暂停持续演示或显著降低非必要绘制；恢复后不应突然补算一段看不见的时间。暂停场景也不必永久以全速更新文字和图像；相机阻尼未收敛时可以继续绘制，稳定后按需刷新。图像参数快速拖动时合并过期请求，旧结果不能覆盖新输入。不要为了本轮改造把所有计算提前搬到 Worker；先测出真实瓶颈。

当前日地月在异步贴图初始化之前就创建渲染器，因此应检查渲染器创建失败能否进入明确错误界面，而不是只在贴图加载的 try/catch 中提示。这里只是静态阅读发现的检查点，尚未经过本手册作者运行确认。[S09]

WebGL 不可用时，二维工具仍应尽可能正常工作；三维工具显示清楚错误与适用的静态说明或已存在片段。R1 不要求给全部三维模型另造等价二维引擎，更不能显示静态截图却保留假的可交互控件。网络、数据或贴图失败只隔离当前模块，不能让整站不可用。

## 9. 深度样板一：日地月，四个模式共用一套可信关系

### 9.1 保留与改造范围

基线已有月相、自转、两种周期、日月食四模式；有空间与地心方向视图、相位快捷按钮、时间控制、参数设置、影锥剖面和模式解释。模型将物理千米坐标与展示缩放分开，相关能力必须保留。[S09]

优先改造 `web/earth-moon/index.html`、`app.js`、`style.css`、模式说明字段及对应启动适配；`physics.mjs` 不作为重写目标。将完整讲义对话框和课程入口移出工具。保留月面标记、单位、比例说明与模型来源，短说明按具体模式重写为独立语境。保持太阳系工具的核心布局不受本样板共享 CSS 波及。

### 9.2 月相：让受光与可见半球成为主角

默认状态先让用户看见一个足够大的月面和可追踪的空间关系。拖动月球或播放时间时，太阳方向、月球位置、观察方向和所见亮面保持一致；观察结果可以放大为主视图，空间关系仍能通过清楚入口返回。不能为了强调太阳把月球和地球缩到看不清，也不能在核心月面周围常驻大段说明。

首次演示可以从弦月开始，拖到新月附近，再走到满月；在适当位置标出“受光的一半”和“看见的一半”的关系。几何受光比例、相位角和空间方位的命名保持原定义，不能混用月面处的相位角与地球处的日月角距。主视图应显示月面变化，数字只负责补充。

尺度开关保留，但标为恢复地球、月球与地月距离的统一比例，不暗示太阳也处于真实距离。改变显示比例或相机不能改变科学受光结果。普通月相演示不应把地球影子当成暗面的来源。

### 9.3 自转：一个固定标记串起过程

保留同步自转与完全不自转对照，但不要仅在端点替换月面图片。以固定在月面的醒目标记追踪公转过程：相同起点分别采用两种自转方式，推进半圈和一圈，观察标记是否继续朝向地球。标记不是地质测绘坐标，应保留教学身份。

为避免“相机跟着转”掩盖差异，默认使用清楚的参照方向；切相机不能改变模型自转方式。两种情况可以使用同一画面依次复现，不必同时增加四个小窗。经度天平动开关保留在扩展设置中，并沿用偏心公转与均匀自转的简化边界，不升级为完整月面姿态模型。

### 9.4 两种周期：放大真正需要解释的那一部分

当前年度小图的画布是190×135，并且藏在空间图角落。新方案不应继续让“地球已经前进”这一关键关系只依赖小图里的读数。将太阳方向变化或日心参照关系提升为当前模式的有效主视图，或在讲到这一关系时切入大图；其他模式不必永久占用这个空间。[S09]

从同一个新月起点连续推进，先到相对恒星方向重复的位置，再到相同月相重复的位置。两个终点用明确标记区分，可以逐段播放、暂停和继续；原有27.32天与29.53天快捷入口用于精确复现，而非替代连续过程。两条进度若保留，应清楚说明计数参照，避免只是两条抽象进度条填满。

不要偷偷更换坐标参照，让地球似乎绕固定在画面上的月球公转。相机或参照变更需要可见提示，并保持同一时刻的对象身份。原模型距离调整未联动改变周期的限制要保留；R1 不通过“顺便变真实”改动这一关系。

### 9.5 日月食：先看对齐，再看遮挡发生

从一次理想化的新月但无食的状态开始，让月球连续经过相应位置，展示其偏离对齐方向；再改变明确的一项或一组条件，重放过程，观察遮挡出现。使用日全、日环、日偏、月全等预设时，要能看到预设改变了哪些参数，不能只让按钮直接切到一个漂亮终点。

当前局部时间、观察点、角圆面与影锥剖面保留；当讲解影锥时让剖面获得足够面积，不必和两幅三维视图同时挤满首屏。局部观察点的东、北偏移是相对月下点的几何设置，不得改名为城市经纬度。当前模型不是固定地点的真实日期接触时刻预测。

太阳角圆面的遮挡与月面照明继续取自物理量，不读取显示放大的球体尺寸。红光选项保持定性，不能赋予可预测的真实月食颜色或亮度。资料中的太阳实际观测安全说明保留，工具演示不提供真实观测操作替代。

### 9.6 本样板验收

四模式各交付一个默认状态、一个主要参数改变、一次复位、一个边界状态和一段15–30秒真实操作录屏。录屏是验证过程连续性的证据，不作为正式教学视频发布；不需要先建设视频制作流水线。

科学回归应覆盖：显示比例不改照明结果；相机变更不改物理状态；同步与固定自转有可复现差别；两种周期按原模型端点定义区分；不对齐时无食、改变对齐或角尺寸后遮挡关系符合原模型。数值容差与样本从原计算、已存在测试和独立依据确定，不能凭本手册设一套虚构的高精度指标。

负责人试用前，Codex应完整播放这些过程并检查主体、标签、参照方向和控制可达性；静态截图只能证明端点布局，不能证明运动已经讲清楚。

## 10. 深度样板二：图像，把“测得的数据”与“看见的颜色”分开

### 10.1 保留现有价值，减少界面绕路

当前图像工具已经有真实 M17 通道、教学计数、像素检查、赋色、拉伸、人工偏移、保留显示对照、放大对照和处理信息保存。先用真实操作核对这些功能，再改进它们之间的关系，不新增一个名称相近的“高级对比”面板。[S10]

主工作区保留两个有意义的图像位置与同一源网格的检查点。主要操作围绕当前任务展开：改变赋色时突出通道对应，改变拉伸时突出显示变换，比较计数时突出源值和噪声。不是每个任务都要默认展开所有通道增益、曝光、黑点、白点、位移、直方图和资料图版。

### 10.2 真实通道：改变颜色，源值不变

默认操作是选择同一像素，将 SHO 改为 HSO，观察显示颜色改变而三通道源值不变。用简洁的通道—显示颜色对应关系解释变化，不强求另外绘制大型流程图。像素位置跨灰度、合成与放大对照保持一致，标记和坐标在键盘或鼠标操作时同步。

需要比较拉伸前后时，使用已有保留对照功能；保留图必须带有当时设置摘要，明确它是冻结的显示结果而不是第二个正在变化的数据集。改变当前图参数不能改变参考图的源身份或悄悄更新其画面。切换数据集后清理不兼容对照并说明，避免假装两个不同来源拥有同一像素含义。

原M17教育数据是经过处理的窄带产品及其降采样数组，不是未经标定的探测器原始帧。显示中的空白/零值拼接边界不是暗云；每通道归一后 RGB 强度不能直接作为元素丰度。上述必要说明应贴近图像，完整来源与单位限制放在可打开的资料区。[S01、S10]

### 10.3 教学计数：明确哪些操作改变测量

教学模式中的曝光、背景、读出和噪声属于合成测量模型；赋色、拉伸和显示增益属于显示处理。界面分组应让两者不同，不能让用户以为拉伸能恢复已经饱和的信息，或减去背景均值会消除随机涨落。

对噪声演示保留可重复的随机种子；复位得到同一初始结果。可以显式提供“重新生成一次噪声”作为独立操作，但不能每拖动一个显示滑杆就重新随机生成源数据。保持原噪声与饱和模型的适用范围，若要改变其数学定义，另列模型改动与验收。

现有人工配准偏移仍称为人工偏移或校正演示，不称为自动天体测量或真实图像标定。对暂时不可载入的真实数据，提供错误和显式进入教学数据的选项，不自动用合成图冒充真实 M17。

### 10.4 本样板验收

固定数据与像素，在不同赋色、拉伸下比较源数组值不变；改变合成曝光后检查测量值的变化；同一输入与种子重复生成相同教学结果；复位、导入和新建对照的语义明确；进入和退出既有放大对照后没有丢失事件、选择或键盘焦点。

原数据、元信息和归一口径留有哈希与来源记录；处理信息导出不误称原始观测数据。二维图像任务在不创建 WebGL 场景的环境下仍应可运行。两模式各有桌面、窄屏截图和真实操作短录屏。M17相关公开分发状态仍按资料记录处理，不因完成界面改造自动转为许可已确认。

### 11.8 恒星：模型浏览不冒充现场求解

| 模式 | 改进目标与边界 |
|---|---|
| `stars/hr` | 让当前例子、坐标方向、温度、光度与半径关系可读；明确构造示例与观测样本的区别。不要只靠区域底色和名称解释全部内容。 |
| `stars/evolution` | 一条模型轨道上的当前点、年龄与表面量同步；按实际选定模型显示，不在质量之间插值创造新轨道。内部示意与真实模型输出分别标识。 |
| `stars/pulsar` | 辐射束、旋转轴、视线与脉冲曲线当前点同步；通过改变视线展示有脉冲与无脉冲。沿用几何模型，不称为实际辐射输运计算。 |
| `stars/collapse` | 先明确当前子任务是坍缩关系还是潮汐尺度，再展示相应变化。不同尺度和教学假设不能混成“完整黑洞模拟”；保留反例和不适用情况。 |
| `stars/ia` | 比较校正前后样本关系，让校正量和残差含义清楚。标明人工模板或合成样本，不把视觉收拢说成真实数据重新拟合。 |

### 11.9 银河与宇宙背景：分别组织空间、方向与频谱

| 模式 | 改进目标与边界 |
|---|---|
| `galaxy/galaxy` | 从盘外、盘内与不同观察方向追踪相同结构；视角切换要帮助解释亮带。解析示意点不称为真实逐星银河重建。 |
| `galaxy/cmb` | 清楚展示全天方向图、投影与选定方向，保留图像来源。不能从JPEG显示颜色反推出精密温差；缺少定量数据就停在图版探索。 |
| `galaxy/cmb-spectrum` | 平均频谱与空间方向图分开解释；曲线、数据点与单位可读。不会因切到某个方向就得到该方向的实测频谱，除非已有相应数据与模型。 |

### 11.10 轨道与航天：连续展示条件和结果

| 模式 | 改进目标与边界 |
|---|---|
| `orbits/orbit` | 在同一高度比较不同横向速度，保持当前位置、轨迹与终态关系清楚。必要时切换近地和整体视图，但不能靠裁切隐藏逃逸或碰撞。 |
| `orbits/transfer` | 两次点火发生在明确位置，点火前后轨道和速度状态对应；让过程连续而非只切换三条椭圆。沿用原转移假设，不扩成任务规划。 |
| `orbits/staging` | 用可理解的质量构成和过程说明分级作用；参数变化与预算结果对应。纯预算关系可以用图表，不要求做假的飞行动画。 |
| `orbits/landing` | 高度、速度、剩余燃料与接地状态共同来自同一过程；改变点火条件有可解释后果。失败状态明确，不添加成功庆祝遮盖模型边界。 |

### 11.11 综合测量：让测量动作真的影响推断

| 模式 | 改进目标与边界 |
|---|---|
| `measure/shadow` | 测量端点、角度、影长与推算高度对应；支持键盘及数值替代操作。标明合成几何，不声称从旁边真实照片直接实测。 |
| `measure/jupiter` | 让周期与轨道尺度的选取进入质量推断；保留量的来源与误差定义。只有输入换算而没有可用观测序列时，明确它是参数推断演示。 |
| `measure/s2` | 分清角尺度、距离和线性尺度对质量推断的作用；显示圆整教学参数身份。不要说成重新拟合银心实测轨道。 |
| `measure/distance` | 把当前方法、输入、输出和误差传播分开；必要时按方法分小视图。对无效或超出定义范围的输入明确处理，不用零值掩盖无解。 |

R2 推荐顺序是：先处理最影响例会使用的光学、行星投影与两种一天，再改进星光和测量，之后按实际需要推进恒星、银河与航天。某一模式若最终证明图版或短片更有效，提出资产化方案并保留原入口迁移记录；不由自动评分器自行删除。这个顺序是建议，不是内容价值排名。

## 12. 视频能力：按实际内容接入，不先建媒体工程

### 12.1 R1 的条件式任务

先检查本地是否已有负责人确认可用的视频及其源码、字幕、封面、来源和版本记录。已存在的视频制作目录不自动纳入运行包，也不因本轮重构删除。没有已确认素材时，本轮只在开发说明中保留接入约定，**不新增空视频页、占位影片、批量制作任务或播放器框架**。

存在可用素材时，先为一个具体内容增加简单播放入口。页面主要空间留给视频，周围只保留必要标题、来源、模型身份和返回工具入口。教学片、真实观测录像、工具录屏分别标明；预录内容不能冒充此刻正在运行的交互仿真。视频本身能讲清的内容，不在外面再铺一页重复字幕。

### 12.2 最小实现边界

优先采用浏览器原生 `<video>` 控制，设置合适的封面、内联播放与元信息预载入提示；默认由用户播放，不自动出声。已经配有讲述的视频附字幕或文字稿，字幕不遮住主体；播放失败有明确提示和可用的文件入口。`preload` 是浏览器提示，不应当作保证下载范围的硬承诺。[S17]

当前服务器的 MIME 表没有列出 MP4、WebM、VTT，文件发送逻辑也没有专门处理媒体范围请求。因此真正加入视频时，还需在受限资源清单下补齐媒体文件服务与寻址验证，而不是只插入一个播放器标签。可由独立发行包的静态服务器承担，也可给本地服务增加经过测试的单范围处理；不要为了视频放开整个工作区。[S08]

需要实现范围请求时，正确处理普通响应、部分内容和不可满足范围，核对响应长度与边界；拖到视频中段、尾段、暂停和再次打开都要实测。R1 没有实际视频，则这些网络功能不必提前实现。[S18]

首个媒体记录只需包含稳定 ID、实际文件、显示名称、真实时长、可选封面与字幕、来源/模型说明及相关工具的普通链接。除非已经真实使用，不新增时间片段编排、统一视频—仿真状态同步、自动转码、云存储、视频编辑器或后台。

### 12.3 不把演示改造成 PPT 式影片

后续制作视频时，先验证一个连续过程：主体足够大，关系逐渐出现，变化由模型或明确叙事驱动。先审一个短段落，再扩成完整成片；不能把提高帧率、减少字幕或让小球旋转当作解决“像PPT”的全部办法。平台本轮只负责使用合格内容，不负责自动保证成片质量。

正式视频与验收录屏分开保存，不能把测试人员操作界面的录屏自动加入公开视频目录。播放平台的完善不能反过来挤占现有演示内容的打磨时间。

### 14.2 视觉与动态证据

所有模式至少保留固定默认状态的布局检查；每个工具选一个代表模式人工查看桌面与窄屏，复杂的模式切换额外取图。两个深度样板的六个模式全部查看默认、关键中间状态和边界状态，并完整播放短录屏。

截图比较要固定浏览器、视口、字体环境、数据、相机和暂停状态；不能在不同环境的图片之间直接用像素差宣称退化。Playwright 的视觉比较可辅助发现布局变化，但基线图片仍需要实际审阅。[S19]

对运动验收不能关闭全部动画后只比较端点。记录播放时的主体可追踪性、参照系、遮挡关系与操作；录屏中的流畅观感不能自动推导 GPU 帧耗时。软件 WebGL、模拟视口、真实设备与现场投影分开标识。

建议选择一个典型例会使用序列持续运行30分钟，包含播放、暂停、切模式、收起面板和往返工具。可以作为接近实际使用的稳定性检查，但不能由一次通过推导长期无泄漏或全部硬件稳定。无法执行时如实记为待进行，不用数秒短测替代名称。

### 14.3 科学验收的三层分工

第一层是**保留性检查**：本轮没有偷偷改变原始正文、数据与模型输出。第二层是**针对性科学检查**：新呈现是否正确使用量、单位、参考系、采样和状态；必要时对选定参数做解析性质或独立参考对照。第三层是**真实教学使用**：讲者和成员能否理解过程、是否值得打开交互工具。

三个层次可以拥有不同状态。原版有来源记录，不等于新视角已科学审校；代码没改模型，不等于说明文案绝对正确；录屏看起来漂亮，不等于机制讲清楚。历史31项Node测试、118项浏览器检查等仅作为旧版本记录保留，不能累加成新版本“科学验收总数”。[S01]

R1 可交付“工程候选版”；现场投影、真实手机与负责人试用尚未完成时，保持具体待验项。不得由Codex、另一个代理或自评分数代替真实完成记录。

### 14.4 应停止发布或暂停相应改动的情况

原始讲义被改写、数据与许可丢失、私人内容将进入发行包、独立包仍依赖课程、旧工具主要功能损坏、物理状态与画面不一致、合成内容被标为真实观测，均不能带着“以后再修”进入正式发布。相关改动退回最近通过点，其他独立任务可继续。

缺少视频、不能立即输出全套PPT、没完成全部37个模式深度重制，不是 R1 工程交付失败；它们属于明确不做或后续阶段。相反，只更换导航与颜色而没有完成依赖拆分、原始资料包和两个样板，不符合 R1 的完成定义。

## 15. 最终交付与后续开发方式

### 15.1 开发者交付给负责人的内容

交付讲义原始资料目录与ZIP、独立Lab运行目录与可分发状态说明、实际生成的兼容阅读副本（若采用）、一份更新后的README和一份持续维护的重构交接记录。给出真实的本地启动命令、预览地址、构建版本和包哈希，不链接不存在的产物。

交接记录至少说明：哪些旧依赖已经拆除；哪些模式完成基础适配；哪些完成深度改造；模型或短说明发生了哪些实质变化；保护文件是否保持；执行了什么检查、用什么设备、在哪个包上执行；哪些失败或未决事项仍存在；旧阅读链接的当前去向；是否含有不能直接公开分发的资产。

截图和录屏提供能够判断关键问题的少量代表证据，完整原始测试记录留在本地审查目录。没有必要把大量重复截图、测试临时视频、用户路径或终端全部输出提交到公开仓库。公开验证摘要可以保留范围与结论，但不能泄露私有材料或凭据。

### 15.2 部署要单独交接

本轮不操作生产。准备部署时列出旧版恢复方法、新运行包根目录、独立讲义地址或资料服务配置、资源与MIME变化、反向代理是否仍需保留、旧链接迁移方案及本项目回滚方法。未经授权，不改PM2、端口、Nginx站点、证书或社团主站路径。

将“本地构建成功”“独立包验证通过”“负责人试用通过”“生产部署通过”分为四个事件；文档日期、产品版本和部署版本分开记录。以共享服务器存在为理由执行全局重启不在本手册授权范围内。[S03]

### 15.3 R2 及以后如何增加内容

完成 R1 后，选择一类真正需要的内容继续打磨。例如先把光学分辨与采样做成可靠的投影工具，再处理火星视逆行；不要把全部37个模式同时交给互不交流的执行者重写。每个新模式或视频都要说明它回答什么问题、为什么需要交互或播放、复用了什么模型与资产，以及如何检查。

高级内容可以是新的讲义包、计算笔记本、数据分析或少量新工具，不要求所有研究流程进入网页。只有重复使用、受众稳定、模型与交互边界清楚的能力才进入 Lab。一个工具可以被多套内容引用，但不接收“第几讲”“本班进度”等课程内部概念。

未来统一媒体入口可以由真实内容逐步长出：先一个视频文件与现有工具共存，再根据实际使用增加检索、片段定位或资料打包。未经实际内容证明，不创建抽象时间线编辑器、所有媒体的统一状态协议或线上制作后台。

**本轮的成功标准是：讲义能够独立保存，Lab能够独立使用，关键演示明显更能讲清关系，现有成果没有被重构破坏。不是目录更多、界面更像平台、按钮更多，也不是报告里的通过数量更大。**

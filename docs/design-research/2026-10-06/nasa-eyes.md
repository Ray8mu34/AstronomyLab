# NASA Eyes：空间探索的界面语法

2026-10-06｜[实际产品](https://eyes.nasa.gov/apps/solar-system/)｜范围为 Eyes on the Solar System，未推及整个 Eyes 产品族。

实看状态：默认太阳系、展开时间控制、点选地球、窄屏地球信息入口。HTML 与三个链接 CSS 均成功获取；大型 app.css 只保留前约 200 KB。比例为截图估计，不是产品规范。暗色场景已查看；没有确认独立的浅色 UI 主题，场景照明开关不能当作主题开关。浏览器操作有超时，时间快进/倒退/暂停与设置各分支未逐项验证。

## Visual Theme & Atmosphere

它首先提供一个可以探索的空间，再把资料和工具挂在空间边缘。选中地球会靠近目标，并将侧栏从故事入口替换为对象信息；选中状态同时进入顶部路径。

关键特征：全视口场景、贴边工具、对象标签、聚焦相机、按对象出现的资料、可展开的时间控制。首屏故事列表和大量轨道也会争夺注意力，不能将其描述为始终无干扰。

## Color Palette & Roles

深色底让模型与轨道承担视觉差异；工具本身多为中性灰，实时状态另有醒目编码。仅记录有来源的值，不为 Lab 复制调色板。

| Hex / 角色 | 出处 | 设计含义 |
| --- | --- | --- |
| `#000000` 场景底 | 实测 body 背景 `rgb(0,0,0)`；app.css 含黑色规则 | 底色后退，让空间对象显现 |
| 中性灰面板、浅色文字 | 实际截图 | 对象资料与场景分层 |
| 状态与轨道的差异色 | 实际截图 | 分开运行状态和对象身份，不能只靠颜色 |

CSS 来源：[app.css](https://eyes.nasa.gov/apps/solar-system/app.css)、[preload.css](https://eyes.nasa.gov/apps/solar-system/preload.css)、[vendors.css](https://eyes.nasa.gov/apps/solar-system/vendors.css)。CSS 中主题相关类名不是双主题可用性的证明。

## Typography Rules

body 实测为 `Metropolis, sans-serif`；app.css 定义 Metropolis、Inter、DMMono。读数、对象标签与资料有层级，不需要在场景上建立网页式大标题序列。

| 角色 | 可确认的规则 |
| --- | --- |
| Display / H1 | 顶部产品名，视觉从属场景；不外推全站字号 |
| H2 / H3 | 对象资料、时间状态分别成组；未提取完整标题尺度 |
| Body | 侧栏用于短介绍，长文通过 Read More 分出 |
| Small | 实测部分控件文字为 14px；不能称全部控件都如此 |
| Mono | CSS 有 DMMono；未证明所有时间读数都使用它 |

## Component Stylings

工具栏将缩放、图层、照明和信息入口放在右侧。对象面板提供 Info / Toolbox / View Options 分组、简介和相关对象；资料深度进一步由 Read More 承接。按钮以低强调面层为主；没有观察到需采用的破坏性按钮样式。

时间栏收起时保留日期、速率与 LIVE，展开后出现倒退、暂停、前进按钮。[展开截图](images/nasa-time-expanded.jpg)证明入口层级，不证明每个按钮的运行行为。画面素材是产品内容，不是应复用的 UI 资产。

## Layout Principles

场景画布覆盖整个视口，但左侧故事或对象面板约占四分之一宽度，顶部、右侧和底部还有覆盖控件；可自由观察区域约为视口的三分之二至四分之三，随状态变化。这里必须区分“画布范围”和“未被遮挡的主体范围”。

点选后地球获得足够尺寸，信息仍贴边。相机聚焦和面板出现是同一个对象上下文的变化；不应为追求卡片整齐把大对象缩成资料卡配图。完整间距、圆角、阴影尺度未抽取，不补造一套 token ramp。

## Depth & Elevation

场景、对象标签、边缘面板、展开工具构成不同层。深色不透明/半透明面层比装饰性阴影更重要。遮挡预算必须按展开状态检查：相机聚焦后仍有许多轨道穿过地球，图层管理对理解很重要。

## Interaction & Motion

实际点选地球后，相机聚焦、侧栏内容、顶部对象名同步更新。空间探索在一个持续场景里发生，时间入口不要求离开场景。不能从本次端点截图判断相机过渡的精确时长、帧率或长期流畅性；hover、键盘 focus 和完整播放路径尚未系统测试。

适合 Lab：选中对象有场内标记与上下文；视角工具和资料分层；时间入口贴近场景。不适合直接照搬：自动聚焦可能中断教师固定参照，故事卡和全部标签会遮挡因果关系；任务浏览不等于参数实验。

## Responsive Behavior

390×844 截图中，顶部收敛为菜单入口，对象资料成为底部信息入口，时间和右侧工具仍贴边；地球近景占主体，更多轨道标签仍带来拥挤。此次从桌面状态调整窄屏，未单独验证手机首次进入流程或底部信息展开后的完整操作。

app.css 的已取片段含 641px、961px、1025px 等条件，并结合高度和方向；preload.css 另含 660px、960px，属于加载页，不能用来解释主应用布局。不是简单以一个宽度断点完成适配。实测桌面 Menu 控件高 40px，但未证明全站触控目标的最小值。

## Agent Prompt Guide

只迁移关系与操作原则，不迁移品牌、字体、贴图或视觉皮肤。

- 提示一：让既有太阳系选中对象、场内标记与对象信息保持一致，保护原场景、材质和相机机制。
- 提示二：把资料深度放入上下文面板，保留主体与当前时间；避免新增故事推荐覆盖演示。
- 提示三：窄屏用一个对象信息入口承接详情，展开时检查主体遮挡和退出后的状态保留。

迭代应检查：对象身份能否追踪；相机是否抢走参照；图层是否过密；面板能否收起；日期/速度是否仍可见。主结论是对象上下文与边缘控制适合空间探索，NASA 的完整任务浏览结构不宜成为所有 Lab 工具模板。
